# Interface language (English / Ukrainian)

The player picks the language in **Settings → Preferences → Language**. It is stored in
`localStorage` (`something2.lang`) and defaults to the browser language (`uk*` → Ukrainian,
anything else → English).

## How it works

`frontend/src/games/something2/src/js/i18n/i18n.js`

- `t("English text", {param})` returns the Ukrainian entry for that exact English string, or the
  English string itself when there is no entry. **The English text is the key.**
- `tn(count, ["{n} point", "{n} points"])` is the plural-aware form. The Ukrainian entry is an array
  `[one, few, many]` stored under the first English form.
- React components call `useLang()` so they re-render on a switch. The canvas redraws every frame,
  so `t()` at draw time is enough.
- Dictionaries live in `i18n/uk/*.js` (one object per area: `game`, `render`, `panels`, `quests`,
  `react`, `data`, `content`). `i18n/__tests__/i18n.test.js` checks every entry keeps exactly the
  `{placeholders}` of its English key, and that areas never disagree on a string.

## Rules for new UI text

1. Every player-visible string goes through `t()`. Interpolation uses `{name}` placeholders, never
   a template literal: `t("Progress {done}/{total}", { done, total })`.
2. Do not build a sentence from translated pieces; word order differs. Translate the whole sentence.
3. Counts use `tn()`. Ukrainian has three plural forms.
4. Text that comes from the server (quest titles, item and creature names, NPC lines) is passed
   through `t()` where it is displayed; add its English text to `uk/content.js` or `uk/quests.js`.
5. Do not translate: hotkey letters, numbers, ids, debug/admin screens, log messages.
6. Tests run in English, so a wrapped string must produce byte-identical English output.
